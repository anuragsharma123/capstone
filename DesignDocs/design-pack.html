/Decisions to know (and push back on if you disagree)

  • An agent is a JSON config document, never generated code. One runtime reads any document — gives us versioning, safety, and cross-workspace publishing.
  • One PostgreSQL for everything, including the admin review queue. Isolation must survive removing the app filter (RLS); decide + resume must be one transaction; "bombardment" is solved with indexes, not a second datastore.
  • Isolation = row-level security keyed on owner_id + tenant_id. Rule 2 and grading check 1 are user-to-user, not just company-to-company. Six tables carry owner_id.
  • The MCP registry is per-user. Everyone registers their own servers and connects with their own token. Simpler, fully consistent RLS.
  • Marketplace + admin-review tables have no RLS — the one deliberate exception. Cross-tenant by design; rows are sanitized on entry; an admin guards the door.
  • Credentials: envelope encryption (per-connection key, KMS-wrapped). For the capstone the "KMS" is one master key in an env var. A single Fernet key would also pass — this is a strengthening, not a requirement.
  • Tools are tagged read/write/destructive at registration by a deterministic classifier (fail-safe to write). The approval gate reads that tag from the DB — never the prompt.
  • Scores are a pure function of the config — no LLM. Every point traceable; publish blocked below threshold; this is how an unguarded write tool can't be published.
  • Auth is middleware inside the App Server, not a separate service.
  • Two clients: the web app and the external API. Marketplace and Admin Review are pages inside the web app; both require login.
